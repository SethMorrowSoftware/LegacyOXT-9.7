# The system libraries that LiveCode Community on Linux needs beyond glibc,
# the GCC runtime (libstdc++, libgcc_s), zlib and OpenSSL, one per line:
#
#   <soname>  <use>  <Debian/Ubuntu package>  <Fedora package>
#
# <use> says what needs the library:
#   core     the engine, even without a user interface (-ui)
#   gui      the engine with its user interface: the IDE
#   browser  the browser widget and revBrowser (CEF 74, x86_64 only)
#
# Debian package names are Debian 12's and Ubuntu 22.04's. Debian 13 and
# Ubuntu 24.04 renamed some for the 64-bit time_t transition (libgtk2.0-0
# is libgtk2.0-0t64 there); apt finds most of them by the old name too, but
# not libasound2, so the CI asks apt-cache and uses the name with "t64"
# where there is such a package.
#
# Read by the Linux CI only (LiveCode's packages have no launcher that
# checks them): it installs the Debian packages on its test runner, and
# tools/ci/check_linux_libraries.py fails when an ELF file of the package
# needs a library (DT_NEEDED), or the engine loads one with dlopen (the
# initialise_required_weak_link_* modules of engine/src/linux.stubs, and the
# Pango modules of engine/src/lnxflst.cpp), that is neither listed here nor
# part of the base system (tools/ci/check_native_deps.py LINUX_SYSTEM) or
# the package.
#
# The engine: glib at start-up (dsklnxmain.cpp), FreeType and Fontconfig
# (DT_NEEDED of the engine itself). With a screen (MCScreenDC::open): X11,
# GObject, GDK, GdkPixbuf and Cairo, and Pango, PangoCairo and PangoFT2 for
# all text. GTK 2 itself is optional to the engine (native theme and
# dialogs), but it is the package that has GDK.
